# Liverary React

React와 JavaScript로 작성한 미래도서관 자유석 서비스다. 기존 목업의 보라색·라벤더 색상, 흰 카드, 얇은 회색 선을 이어받았다. 화면·자산·로직은 이 폴더에서 관리한다.

## 실행

권장 실행 버전은 Node.js 24.19.0이다. 이 버전에서 빌드와 테스트를 확인했으며 `.node-version`에도 기록했다. Node.js 22 LTS를 사용한다면 22.12 이상이 필요하다.

현재 PC의 Node.js 24.11.0에서는 빌드 프로세스가 오류 메시지 없이 종료되는 현상이 있었다. 24.19.0에서는 같은 코드의 빌드가 정상 완료됐다. 이 현상이 발생하면 먼저 `node --version`을 확인한다. 전역 Node 설치나 설정은 변경하지 않았다.

```powershell
cd "C:\Users\CGB\OneDrive - KNU\바탕 화면\Liverary\liverary-react"
npm install
npm run dev
```

브라우저: http://127.0.0.1:5173/

```powershell
npm run build
npm run preview
npm test
```

`build` 결과는 `dist/`에 생성된다. `preview`는 http://127.0.0.1:4175/ 에서 빌드 결과를 연다. `index.html`은 React를 실행하는 진입점이며 화면과 로직은 `src/`의 JSX·JavaScript 모듈에 있다.

## 화면

하단 메뉴는 `자리 · 소식 · 홈 · 기록 · MY` 순서다. 홈은 중앙에 둔다.

- 자리: 1층 ④ We플레이스 자유석 목업 42개 선택 지점의 번호형 2D 배치도·목록, 창가/콘센트/소파/테이블 필터, 좌석 상세
- 소식: 이벤트·꿀자리·스터디 카드, 상세 보기, 관심 소식 저장
- 홈: 좌석 현황, 현재 이용 중인 좌석, QR 이용 진입
- 기록: 오늘·이번 주 순공시간, 완료한 기록, 공유 카드
- MY: 로컬 닉네임·학과 설정, 저장한 소식, 좌석 QR 생성

이용 흐름은 `좌석 접속 → 이용 시작 → 집중 시작 → 일시정지·재개 → 이용 종료 → 기록·빈자리 반영`이다. QR 화면과 집중·완료 화면에서는 작업에 필요한 버튼만 표시한다.

## QR 접속

좌석별 주소는 다음과 같다.

```text
http://127.0.0.1:5173/?seat=1F-W01
http://127.0.0.1:5173/?seat=1F-W51
```

MY → 좌석 QR에서 원하는 좌석의 QR을 생성하고 SVG로 저장한다. 스마트폰 기본 카메라로 이 QR을 찍으면 좌석별 페이지가 열린다. 홈의 QR 버튼은 번호 입력 대신 QR 인식 화면을 연다.

- QR 스캔: ‘카메라 켜기’를 누르고 권한을 허용하면 후면 카메라 우선으로 좌석 QR을 읽는다. 인식되면 해당 자유석 이용 화면으로 이동한다.
- QR 사진 불러오기: 기기에 저장한 QR 이미지에서 좌석을 읽는다. 10MB 이하 이미지 파일을 지원한다.
- 예제 QR: 현재 이용 가능한 자유석의 QR 이미지를 만들고 ‘예제 QR 인식’으로 실제 이미지 해석을 수행한다. 다른 기기나 인쇄물이 없어도 한 휴대폰에서 체험할 수 있다.
- 배치도에서 자리 찾기: 카메라나 QR 없이 배치도로 이동한다.

인식 결과는 현재 자유석 목록의 ID로만 확인하며 QR에 담긴 외부 사이트로 이동하지 않는다. 단독 숫자·잘못된 주소·이전 15–23번 PC 예약석 QR은 거부한다. 이용 중인 좌석은 신규 이용할 수 없다. 사진·영상은 이 브라우저 안에서 처리하며 서버로 업로드하지 않는다. 창 닫기·화면 이동·방법 전환·탭 숨김·인식 완료 시 카메라 트랙과 스캔 타이머를 정리한다.

웹페이지 안의 실시간 카메라는 HTTPS 또는 localhost 보안 환경과 카메라 권한이 필요하다. HTTP LAN 주소에서는 카메라가 제한되지만 QR 사진·예제 QR 체험은 가능하다. 배포 후 실시간 스캔은 HTTPS 주소에서 확인한다. [브라우저 카메라 조건](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

실제 휴대폰에서 확인하려면 PC와 휴대폰을 같은 네트워크에 연결하고 다음 명령으로 실행한다.

```powershell
npm run dev:lan
```

Vite가 출력하는 `Network` 주소로 페이지를 연 뒤 QR을 생성해야 휴대폰에서도 접근할 수 있다. `127.0.0.1`은 각 기기 자신을 가리키므로 PC의 localhost QR은 휴대폰에서 PC 서버로 연결되지 않는다. 배포 후에는 배포 주소를 열어 생성한 QR을 사용한다.

## 기록과 저장

- React hook이 좌석 상태와 이용·집중·일시정지 상태를 관리한다.
- 시간은 실제 시각으로 계산하며 새로고침 후에도 복원된다.
- 한국 시간 자정과 월요일을 기준으로 집중 구간을 나누어 오늘·주간 시간을 계산한다.
- 종료 시 좌석을 다시 빈자리로 바꾸고 같은 이용 기록을 중복 저장하지 않는다.
- 데이터는 `localStorage`의 `liverary-react-state-v1`에 저장한다.
- 이전 24석 목업에서 저장한 기록·프로필·관심 소식은 보존한다. 이전 좌석의 진행 중 이용은 종료할 수 있지만 새 이용은 현재 We플레이스 좌석에서만 시작한다.
- 앞선 We플레이스 14석 목업의 `1F-W01`–`1F-W14` ID와 이후 추가한 `1F-W24`–`1F-W51` ID를 유지한다. 현재 자유석 목업 42개로 범위를 조정해도 기존 상태·기록·진행 중 이용을 보존한다.
- 이전 PC ID `1F-W15`–`1F-W23`은 다른 좌석에 재사용하지 않는다. PC 기록과 진행 중 이용은 복원·종료할 수 있지만 선택 목록·QR 생성·신규 이용·자유석 집계에서는 제외한다.
- 닉네임·학과는 이 기기의 프로필이다. 학교 계정 인증이나 서버 로그인으로 처리하지 않는다.
- 같은 브라우저의 탭 사이에는 저장 변경이 반영된다. 다른 사용자·기기 사이의 서버 동기화는 아직 연결하지 않았다.

기록 목록 또는 종료 화면에서 공유 카드를 열면 해당 기록으로 구성한 화면을 그대로 PNG로 저장한다. 임의 시간이나 별도 생성 이미지를 넣지 않는다. 파일 공유를 지원하는 브라우저에서는 공유 시트가 열리고, 지원하지 않으면 PNG 저장으로 동작한다.

## 이미지

모든 이미지와 SVG는 프로젝트 내부에 저장한다. 도서관 사진은 강원대학교 AI융합학과 공식 홈페이지의 미래도서관 이미지이고, 곰두리는 학교 공식 자산이다. Liverary 로고와 아이콘은 프로젝트용 SVG로 제작했다. 사진을 실제 좌석 배치도로 사용하지 않는다.

각 파일의 원본 주소와 용도는 `src/assets/SOURCES.md`에 있다. 빌드에서도 자산을 별도 파일로 출력하며 런타임에 외부 사진·폰트 서버를 요청하지 않는다. QR 해석은 [jsQR 1.4.0](https://github.com/cozmo/jsQR)을 사용한다. Apache-2.0 라이선스 원문은 `public/licenses/JSQR-LICENSE.txt`에 보존하고 빌드에도 포함한다.

## 현재 데이터 범위

현재 목업은 미래도서관 1층 공식 안내도의 ④ We플레이스 자유석에 한정한다. 사용자 설명에 따라 좌측 PC 예약석 9개는 우리 서비스에서 제외한다. 사진 기준으로 창가 바 6개, 파란 공통 소파 8개, 작은 테이블 16개, 큰 흰 테이블 6개, 개별 소파 6개의 이용 지점을 배치했다. 선택 가능한 42개는 프로젝트용 목업 수량이며 학교가 확인한 공식 정원이 아니다.

01–06번은 창가 바, 07–10번과 11–14번은 파란 유선형 공통 소파 두 묶음 각 4개다. 이전 15–23번 PC ID는 이력 보존용으로만 남기고 빈 번호를 다른 좌석으로 채우지 않는다. 24–39번은 작은 테이블 네 묶음 각 4개, 40–45번은 큰 흰 테이블과 연결된 U자 소파의 임시 이용 지점이다. 46–51번은 사진에 보이는 개별 소파 세 쌍의 6개 지점으로, 앞선 논의의 8개를 확정한 수량이 아니다. 번호와 분할은 체험용이며 학교가 공표한 공식 좌석 번호·정원·예약 가능 수량을 뜻하지 않는다.

공식 전체 1층 안내도와 사용자가 제공한 VR 화면에서 상대적 배치만 참고했다. PC 공간은 왼쪽에 선택 불가 참고 영역으로 남기고, 그 앞에 작은 테이블 네 묶음을 표시한다. ③ 브라우징 밸리 쪽에는 큰 흰 테이블 한 개와 U자 소파를 놓는다. PC 반대편 오른쪽 직선 창면에는 개별 소파 세 쌍을, 아래쪽 짧은 곡선 창면에는 바를 놓는다. 타일 로비의 베이지 매트에는 사선으로 떨어진 두 파란 소파를 표시한다. 세부 위치와 가구 치수는 실측한 도면이 아니다. PC 외의 회색 가구도 자유석 번호 표식이 있으면 선택 대상이며, 배경 색만으로 선택 가능 여부를 판단하지 않는다.

좌석 상태는 이 브라우저의 목업 데이터다. 학교 예약 시스템·혼잡도 API·학교 인증과 연결하지 않았다. 빈자리를 클릭하면 좌석 상세 → 이용 시작 → 집중 측정으로 이어지며, 예약석을 사전 예약하는 기능이 아니다. 배치도 자산과 VR 참고 자료는 `src/assets/floorplans/`, 좌석 좌표는 `src/lib/wePlace.js`에서 관리한다.

배치도는 100% 전체보기부터 최대 400%까지 확대할 수 있다. 전체보기는 가구와 좌석의 상대적 위치를 확인하는 화면으로, 모바일에서 선택 영역이 작다. 좁은 화면에서는 300% 이상 확대해 선택하는 것을 기준으로 한다. 마커는 1200 × 1500 배치도 좌표계에서 지름 80의 원형 클릭 영역이다. 320–430px 화면의 300% 확대에서 선택 영역 지름 57.19–77.59px와 지도 내부 스크롤 이동을 확인했다.

기존 PC 기록·진행 중 이용 UI 복원은 이번 브라우저 검수에 포함하지 않았으며 보존·종료와 자유석 집계 비반영은 모델 테스트로 확인했다. 모바일 화면 크기 검수는 Chrome 뷰포트 기준이다. 실제 iPhone/Safari·Android에서 가상 키보드, 카메라 QR 진입, 파일 저장·공유는 배포 주소로 별도 확인해야 한다.

개발 서버는 Windows 파일 잠금으로 종료되는 것을 막기 위해 검수 산출물 폴더 `output/`과 `.playwright-cli/`를 파일 감시에서 제외한다.

브라우저 검수 결과물은 Git에서 제외되는 `output/playwright/`에 저장한다. `node_modules/`, `dist/`, 테스트 브라우저 데이터 역시 Git에 포함하지 않는다.
